# マルチモーダル設計仕様書

画像と言語を同じ空間で扱う部分、および胸部X線に固有の処理（胸部野・分類器・U-Net・

システム全体の構成は [DESIGN.md](DESIGN.md)、運用手順は [OPERATIONS.md](OPERATIONS.md)。

## 1. 使用モデルとライブラリ

### 1.1 モデル

| 用途 | 既定 | 次元 | ライセンス |
|---|---|---|---|
| 1 段目（画像・テキスト） | **BiomedCLIP**<br>`microsoft/BiomedCLIP-PubMedBERT_256-vit_base_patch16_224` | 512 | MIT |
| 2 段目の backbone | **RAD-DINO**<br>`microsoft/rad-dino` | 768 | MIT |
| 2 段目（採用） | **胸部野の分類器のプロファイル**（自作。RAD-DINO の特徴から学習） | 15 | - |
| 肺野の分割 | **U-Net**（自作。CheXmask を教師に学習） | - | - |

いずれも**研究目的**での公開である。RAD-DINO の公開元は「臨床実践での使用を意図
しない」と明記している。本システムも研究用途に限る。

`EMBEDDING_BACKEND` / `EMBEDDING_FINE_BACKEND` で切り替えられる。

| 値 | 内容 |
|---|---|
| `deterministic` | 決定論的スタブ。配線とスキーマの確認用。**医学的な意味は無い** |
| `biomedclip` | BiomedCLIP |
| `rad-dino` | RAD-DINO 単体（768 次元。テキストを扱えない） |
| `chest-profile` | **採用構成**。胸部野で pooling した RAD-DINO の特徴を分類器で 15 次元へ |
| `none` | 2 段目を使わない |

### 1.2 ライブラリ

| 層 | 主なもの |
|---|---|
| 推論（学習） | torch 2.5.1 / torchvision / open_clip_torch / timm / transformers |

## 2. マルチモーダル設計

### 2.1 何と何を同じ空間に置くか

BiomedCLIP は画像とテキストを同じ 512 次元空間へ写す。これにより

- **画像 → 画像**: 胸部野の crop どうしを比べる（`IMAGE_SEARCH_STRATEGY=coarse_to_fine` のときの 1 段目。
  既定では画像だけの検索に BiomedCLIP を使わず、所見プロファイルで比べる。§4）
- **テキスト → 画像**: 所見の文から画像を探す
- **両方**: 重みを付けて混ぜる（`HYBRID`）

が 1 つの索引で済む。

### 2.2 日本語の扱い

**外部の翻訳 API へ医療情報を出さない。** BiomedCLIP の text encoder は英語モデル
なので、日本語入力は承認済みのローカル辞書（`ja_en_medical.json`、72 語句）で
英語化する。

```
「右上肺野の結節影」 → "pulmonary nodule in the right upper lung field"
```

**辞書で処理できない自由文は翻訳せず 422 で返す。** 品質を保証できない翻訳で
検索させるより、できないことを伝える方が良い。画面には登録済みの定型所見を
一覧で出す。

所見ラベル（`Fibrosis` など）も日本語で表示し、絞り込みも日本語で受ける。対訳と
言い換えは `nihcc_rag.csvspec` に 1 か所だけ置き、API から画面へ配る。

### 2.3 2 段目にテキストが効かない構成がある

`rad-dino` と `chest-profile` は text encoder を持たない。したがって
`TEXT_TO_IMAGE` / `HYBRID` では **2 段目が自動的に無効**になり、1 段検索で答える。
応答の `models.rerank` にその旨が出る（`disabled-single-stage`）。

逆に画像だけの検索（`IMAGE_TO_IMAGE`）は、既定で BiomedCLIP を使わず、所見プロファイルで
全画像を厳密に比べる（`profile-exact-full-scan`。§4.1）。

## 3. 胸部X線のハーネス設計

### 3.1 前処理

```
  原画像 → 百分位 clip（0.5% / 99.5%）→ 0-255 へ → 極性の統一 → 短辺 1024 へ縮小
```

**極性の統一**が要る。正常な胸部X線では側方（肺野）が中央（脊柱・縦隔）より暗い。
逆転している画像があるので、その関係を見て必要なら反転する。

この前処理は `image_pipeline.pipeline.normalize` の 1 か所だけにある。**学習でも
推論でも同じ関数を通す。** ずれると入力の分布が変わる。

### 3.2 評価の指標

ラベルが**画像単位**しか無いことが、この課題の本質的な制約である。検索の単位を
画像 1 枚にしたので、画像単位のラベルから作った指標がそのまま主指標になる。

| 指標 | 何を測るか | 扱い |
|---|---|---|
| **画像単位 AUC** | 分類器が所見を当てられるか | **主指標**（患者単位分割の test） |
| **Test B（所見の enrichment）** | 似た症例の上位 K に同じ所見が来るか | **主指標**。lift = 適合率 / 基準率 |
| 正解 box の被覆率 | 正解 box が胸部野に入るか | 枠の妥当性（胸部野 99.7%） |
| Test A（同一患者の再現） | 天井に張り付く | **使えない** |

> **帰無（null）を必ず測る。** 画像の統計量だけ（医学的意味なし）に分類器を載せても
> AUC 0.696 に届く。帰無を測らなければ、撮影条件の相関を所見の検出と取り違える。

## 4. ベクトル多段検索

### 4.1 検索の進め方

検索の種類で進め方が違う。応答の `query.strategy` と `models.rerank` に、実際に使った
進め方が出る。

| 検索 | 進め方（`query.strategy`） | `models.rerank` |
|---|---|---|
| 画像だけ（既定） | `profile`: 所見プロファイル（15 次元）で**全画像を厳密に**比べる | `profile-exact-full-scan` |
| 画像だけ（`IMAGE_SEARCH_STRATEGY=coarse_to_fine` か要求の `strategy`） | `coarse_to_fine`: BiomedCLIP の HNSW で候補 → プロファイルで再スコア | `two-stage-coarse-to-fine-exact` |
| 文章・画像＋文章 | `coarse_to_fine` か、プロファイルが使えなければ `coarse_only` | 同上 / `disabled-single-stage` |
| `rerank=false` | `coarse_only`: BiomedCLIP だけ | `disabled-single-stage` |

```
  画像だけ（既定）
    └→ 15 次元のプロファイルで全行を厳密に比べる → 上位 k 件（索引なし）

  2 段検索（文章を含む検索、または切り戻したとき）
    ├→ 1 段目: HNSW で候補 k×4 件（近似。BiomedCLIP、胸部野 crop）
    └→ 2 段目: 候補だけを 15 次元のプロファイルで厳密に再スコア → 上位 k 件
```

**画像だけの検索を全件検索にする理由**: 2 段検索では、1 段目が拾わなかった画像は
どれだけ所見が合っていても並べ替えの対象にならない。1 段目の候補は最大 1,000 件
（全体の約 0.9%）である。実際の検索経路（API 経由）で両者を比べた結果
（上位 20 件の lift、所見ごと 50 クエリ）:

| 所見 | 2 段検索 | **全件検索** |
|---|---:|---:|
| 結節 | 1.91 | **2.43** |
| 肺炎 | 1.25 | **2.51** |
| 肺気腫 | 5.93 | **8.96** |
| ヘルニア | 38.2 | **139.2** |

14 所見中 13 所見で全件検索が上回り、ベクトル検索の p95 も 2 段検索の 290 ms に対し
24 ms である（HNSW の ef_search 1,000 の探索が要らないため）。15 次元 × 11 万行の順次走査は
Citus が 30 shard に分けて並列に行う。

文章を含む検索で全件検索を使わないのは、プロファイルが画像から作るもので、文章の
意味が順位に入らなくなるためである。

### 4.2 プロファイルが 15 次元である理由

**高次元の方が良いとは限らない。** 胸部野の全量の評価で、同じ特徴を 768 次元のまま
比べた場合と、分類器の 15 次元プロファイルで比べた場合の Test B（上位 20 件の lift）は
次のとおりである。

| 所見 | 768 次元の特徴（標準化） | **15 次元のプロファイル** |
|---|---:|---:|
| 心拡大 | 4.60 | **10.37** |
| 気胸 | 4.61 | **5.56** |
| 腫瘤 | 2.83 | **4.76** |
| 結節 | 2.01 | **3.07** |
| 無気肺 | 1.74 | **2.41** |

理由は 3 つある。

1. **プロファイルの比較は近似探索ではない。** 索引が無いので「高次元だと索引の精度が上がる」
   という利点が働く場所がない
2. **15 次元は 768 次元空間を所見の方向から見たものである。** 分類器は単層の
   線形写像（`W` は 768×14）で、所見を線形に予測する 14 方向へ射影している。
   捨てているのはそれと直交する 754 方向
3. **15 という数はラベル空間が決めている。** 14 所見 + 正常らしさであって、
   検索のハイパーパラメータではない

> **この比較は交絡している。** 測ったのは「768 次元の自己教師あり生特徴」対
> 「15 次元の教師あり射影」で、同じ教師ありで出力次元だけを変えた比較はしていない。
> 言えるのは「教師ありの射影が生の高次元を上回った」までである。

### 4.3 スコアの扱い

順位は 1 本なので、分布を揃える校正は要らない。2 段検索で並べ直した候補は `reranked` が立ち、1 段目の類似度
（`coarse_similarity`）も併せて返す。全件検索の候補は BiomedCLIP の類似度を計算しない
ので `coarse_similarity` は null、`reranked` は false になる。

### 4.4 胸郭の形による検索

別軸として、肺野全体の形（16 次元）で並べる欄がある。気胸は肺が虚脱して縮み、
心拡大は心陰影が広がって肺が外へ押される。**画素の見え方ではなく形に出る**所見の
ための軸である。

**所見の判別器ではない。** 判別能は形状の他の記述子に劣ることを測定済みで、
「似た体格・似た写り方の症例を並べて見比べる」道具として位置づける。

画面では候補も検索元も**肺野の外周を描いて**並べる。何を「肺野」として比べたのかが
見えないと、脊柱・心陰影・横隔膜が正しく抜けているかを確かめられない。

## 5. 胸部野のデータ設計

**検索の単位は画像 1 枚の胸部野**（肺野＋縦隔＋横隔膜）である。ラベルが画像単位で、
部位単位の正解が無いためである（[DESIGN.md](DESIGN.md) §1.1）。

**ROI**（Region of Interest、関心領域）は、ここでは胸部野を指す。

### 5.1 何を作るか

```
  正規化 → U-Net（右肺・左肺・心臓）→ 3 つの和の凸包 → 下へ帯 → 全周へ薄く
                                                  ↓
                     胸部野 mask・肺野 mask・形状ベクトル・埋め込みモデルへの入力
```

1. 右肺・左肺・心臓の和の**凸包**で埋める。縦隔・心陰影・気管と、両側の肋骨横隔膜角を
   結んだ線より上（横隔膜ドーム）が入る
2. **下方向へだけ**肺野の高さの 10% を足す。鈍化した肋骨横隔膜角と横隔膜を含める
3. 全周へ肺野の幅の 2% 広げる。胸膜（気胸の外縁）を含める

正面像では脊柱が縦隔と重なって写るので、**脊柱だけを除くことはできない**。

脊柱の推定や葉の分割は行わない。全量での抽出失敗は 54 / 112,120 枚で、すべて
肺野が小さすぎた画像である。

### 5.2 評価と本番で同じ関数を使う

正規化 → 分割 → mask → 縮小 → PNG 化を `image_pipeline.chest` の
`extract_chest` / `chest_model_inputs` に閉じ込め、評価スクリプトと roi-service の
両方がこれを呼ぶ。**分類器は評価スクリプトが作った特徴で学習している**ので、本番の
入力が 1 画素でも違うと、例外を出さずに確率だけがずれる。

- 埋め込みモデルへの入力は roi-service が作り、ingest-worker と backend-api は
  作り直さずにそのまま渡す
- 本番では `chest_image_eval.py verify-ingest` が、roi-service の入力と評価の入力の
  一致（1 バイト単位）と、確率の一致を確かめる

### 5.3 肺野の取り方は U-Net が必須

| profile | 取り方 | 入力 |
|---|---|---|
| `nihcc-unet-local-v1` | U-Net（縮小版。分類器はこれで学習） | 160px |
| `nihcc-unet-v1` | U-Net（本番用） | 384px |
| `nihcc-classical-v1` | 規則ベース。**心臓を出さないので胸部野には使えない** | - |

**入力解像度が違うモデルは互換ではない**ので profile を分けてある。分類器は学習に
使った profile を記録して持ち、取り込みワーカーが起動時に roi-service と突き合わせる。

### 5.4 profile 全体が再現キーになる

`algorithm_version` + profile 全体の SHA-256 が `roi_model_version` である。
**継承の仕組みを入れていない**のは、再現キーが profile 全体を覆うという性質を
保つためで、そのぶん profile 間で節が重複する。

### 5.5 品質検査

肺野が画像の 2% 未満なら抽出不能（422、`LUNG_TOO_SMALL`）。片肺が見つからない・
左右差が大きい・肺野が広すぎる場合は旗を立てて `ROI_UNCERTAIN`（信頼度 0.5）にし、
取り込みは止めない。気胸や大量胸水による片肺の虚脱でも起きるためである。

## 6. 胸部野の分類器

### 6.1 なぜ学習が要るのか

教師なしの外観埋め込み（BiomedCLIP・RAD-DINO の生の特徴）は、撮影条件と体格を
捉えるだけで、所見の一致はほとんど引けない。単位が画像 1 枚なので画像単位のラベルが
そのまま教師データになり、所見ごとの線形分類器を学習できる。部位ごとの所見を推定する
MIL（多重インスタンス学習）は要らない。

### 6.2 構成

```
  全体画像（518 四方）+ 胸部野 mask → RAD-DINO（凍結）→ patch token を mask で加重平均
                                                        ↓
                                      768 次元（L2 正規化）→ 標準化（train の統計）
                                                        ↓
                                      所見ごとの線形 + sigmoid → 14 所見の確率
                                                        ↓
                                      + 「正常らしさ」→ 15 次元（L2 正規化）= プロファイル
```

- backbone は凍結し、線形の頭だけを学習した（患者単位分割 70 / 10 / 20）
- 確率は 2 段目のプロファイルと、画面の「所見の推定」の両方に使う
- 推定は取り込み時に計算して `finding_estimate` に保存し、検索のたびには計算しない

### 6.3 成績（全量。test 22,983 枚）

| 表現 | 画像単位の平均 AUC | 95% 区間 |
|---|---:|---|
| **胸部野 mask で pooling（採用）** | **0.833** | [0.824, 0.839] |
| 肺野 mask で pooling | 0.829 | [0.821, 0.835] |
| 画像全体で pooling | 0.826 | [0.816, 0.832] |
| 胸部野を黒塗りした crop | 0.815 | [0.805, 0.821] |
| 帰無（画像の統計量） | 0.696 | [0.686, 0.705] |

帰無が高いのは、撮影条件（ポータブル撮影など）が所見と相関しているためで、画像の
中身から得た分は帰無への上乗せ（0.137）と見るのが妥当である。

### 6.4 成果物

`nihcc_rag.chest_head.ChestHead`。標準化の平均・標準偏差、線形の重み、所見の並びに
加えて、**特徴の作り方**を持つ。

| 照合する項目 | 理由 |
|---|---|
| backbone のモデル名と revision | 重みが変わると同じ名前で別の特徴になる。**未固定（`unpinned`）は拒む** |
| pooling の解像度（518） | patch grid と mask の縮約が変わる |
| 胸部野 mask の作り方（10% / 2%） | 枠が変わると pooling の範囲が変わる |
| U-Net の profile | 肺・心臓の mask が変わる |

embedding-service が backbone と解像度を、ingest-worker が mask と profile を、起動時に
照合し、違えば止める。書き出しは `scripts/export_chest_head.py`。

### 6.5 分類器は病変の位置をほとんど示さない

分類器は線形なので、所見の logit は 37×37 の区画ごとの寄与の和に**厳密に**分けられる
（embedding-service の `/api/v1/embeddings/chest-map`）。この地図の最大の区画が正解 box
（`BBox_List_2017.csv`）に入る割合を測った（388 枚）。

| 所見 | 地図の最大点 | 胸部野の無作為点 | 肺野の白い点 | 判定 |
|---|---:|---:|---:|---|
| 腫瘤 | **51.8%** | 8.0% | 5.9% | 位置を示す |
| 浸潤影 | 39.0% | 20.8% | 11.4% | 2 倍の線に届かず |
| 肺炎 | 35.8% | 19.1% | 12.5% | 同上 |
| 結節 | 0.0% | 1.0% | 0.0% | 示さない |

- **位置を示すのは腫瘤だけ。** 大きさは 4 所見とも示さない（順位相関 ≤ 0.28）。形は正解が
  矩形しか無いので測れない。Fibrosis は正解 box が無い
- **「肺野の白い点」は無作為以下で、位置の手掛かりにならない。** 肋骨・血管・鎖骨の
  重なりも白い
- 画像単位のラベルで学習した分類器と、凍結した ViT の patch 特徴の限界である。
  位置・大きさ・形を検索に使うには、正解 box や輪郭を持つ外部データで病変検出モデルを
  学習する必要がある。検索の段数を増やしても解決しない（位置の表現が無いため）

## 7. U-Net の設計

**U-Net は略語ではない。** ネットワークの形が U 字（縮めてから広げ、同じ高さどうしを
横に繋ぐ）であることに由来する。Ronneberger ら（2015）が生物医学画像の
セグメンテーション（画素ごとの分類）のために提案したもので、ここでは**肺野の
切り出し**に使う。

### 7.1 なぜ U-Net を使うのか

輝度の閾値による規則ベースの肺野抽出（`nihcc-classical-v1`）は **corpus の 23.8% で
破綻する**（Dice < 0.7 または抽出失敗）。

破綻の仕方は「大きさ」ではなく「場所」である。肺ではなく頸部・肩・縦隔・腹部を
掴む。規則の調整では直らない。

### 7.2 教師データ

**CheXmask Database v1.0.0**（PhysioNet, CC BY 4.0）。ChestX-ray8 すなわち本システムが
使っている画像そのものに、左肺・右肺・**心臓**の mask が付いている。

> **専門家の手描きではない。** HybridGNet という模型が作り、Reverse Classification
> Accuracy で品質を推定したものである。したがって Dice の絶対値を実力と読まない。
> 意味があるのは規則ベースとの差と、目視での破綻の減り方である。

### 7.3 構成

| | |
|---|---|
| 入力 | 1 チャネル、384×384（前処理は推論時と同じ `normalize`） |
| 出力 | 3 チャネル（右肺・左肺・心臓） |
| 深さ | 4 段、基幅 32（約 7.8 M パラメータ） |
| 損失 | BCE + soft Dice |
| 水増し | 回転 ±10°・拡大 0.9〜1.1・平行移動・明るさ・**水平反転** |

### 7.4 実装上の要点

- **分割は患者単位。** 同じ患者の画像が学習側と検証側に跨がると成績が実力より
  良く出る
- **水平反転では右肺と左肺の channel も入れ替える。** 入れ替えないと左右を
  取り違えた模型になる
- **ラベルは 1 枚の uint8 に bit で詰める**（1=右肺 2=左肺 4=心臓）。心臓は肺と
  重なり得るので排他的な多値にはできない
- **確率のまま元の解像度へ戻してから閾値を掛ける。** 先に閾値を掛けて拡大すると
  境界が階段状になり、形状の特徴量が荒れる

### 7.5 成績

| | 規則ベース | U-Net（160px の縮小版） |
|---|---|---|
| Dice 中央値 | 0.828 | **0.968** |
| Dice < 0.7 | 22.2% | **0.4%** |
| 抽出失敗 | 2.0% | **0.1%** |
| 実効的な破綻 | **23.8%** | **0.5%** |

無作為 1,000 枚。未知の患者 748 枚だけでも中央値 0.968 で変わらない。

> CheXmask で学習し CheXmask を参照に評価しているので、**この数字は高く出る方向に
> 偏っている。** 意味があるのは破綻が 23.8% に対して 0.5% という差である。

### 7.6 配信

学習は torch（専用イメージ）、推論は **onnxruntime のみ**。ONNX は重みを含む
1 ファイルにまとめ、model volume へ read-only で mount する。

profile の `input_size` とモデルの入力が食い違うと onnxruntime が分かりにくい例外を
投げるので、**起動時に突き合わせて名前付きの誤りで止める。**

## 8. 評価の進め方

### 8.1 手選びの数枚で判断しない

採否は**無作為抽出**で測って決める。手選びの数枚の目視では、全体の何割で破綻するかが
見えない。**手選びの画像は症状の再現にだけ使い、採否の判断には使わない。**

### 8.2 測る道具

| 対象 | 道具 |
|---|---|
| ROI | `scripts/eval_roi_dice.py`（CheXmask を参照に Dice / IoU） |
| 胸部野・分類器 | `scripts/chest_image_eval.py`（被覆率・教師データ・AUC・Test B・帰無） |
| 本番の検索経路 | `scripts/chest_search_eval.py`（API 経由の Test B。全件検索・2 段検索・1 段目だけを比べる） |
| 病変の位置 | `scripts/chest_lesion_map_eval.py`（分類器の地図と正解 box） |
| 本番の特徴の一致 | `scripts/chest_image_eval.py verify-ingest` |
| 部位単位の信号（本番の経路では使わない） | `scripts/region_*.py`（肺の部位ごとの信号・MIL の評価） |

いずれも**帰無との比較**を伴う。帰無を測らずに「効いた」と言わない。
