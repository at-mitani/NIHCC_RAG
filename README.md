# NIHCC 胸部X線画像検索ローカルRAGシステム

胸部X線画像の**胸部野**（肺野＋縦隔＋横隔膜）どうしを比べて検索するシステム。
画像を投げれば似た症例が、所見の文を投げれば該当しそうな症例が並ぶ。各候補には、
胸部野から学習した分類器による**所見の推定**（研究用・診断ではない）が付く。

> 部位単位の正解データが無いため、肺を部位に分けず、画像 1 枚の胸部野を 1 単位にしている。

外部サービスへ医療情報を送らない。すべて手元の環境で完結する。

> ## 研究用途に限る
>
> **診断に使わない。** データセットのラベルは放射線科レポートから NLP で導いたもので、
> 専門家が画像を見て付けたものではない。検索結果にも常にその旨の警告が出る。

## 1. 必要なもの

| | 最低 | 推奨 |
|---|---|---|
| OS | Linux / Windows（Docker Desktop） | Ubuntu 24.04 以降 |
| CPU | 4 コア | 8 コア以上 |
| メモリ | 16 GB | 32 GB |
| ディスク | 60 GB | 200 GB（全 11 万枚を入れる場合） |
| GPU | 不要（CPU で動く） | NVIDIA（取り込みが 5〜10 倍速い） |

Docker と Docker Compose v2 が要る。GPU を使う場合は NVIDIA Container Toolkit も。

データセット（NIH ChestX-ray14）は別途入手して `NIHCC/` へ置く。

## 2. インストール

構築手順は環境ごとに分かれている。

- 手元の PC → **[SETUP_LOCAL.md](SETUP_LOCAL.md)**
- GPU 付き EC2 → **[SETUP_EC2.md](SETUP_EC2.md)**

最短の流れだけ示す。

```bash
git clone git@github.com:at-mitani/NIHCC_RAG.git
cd NIHCC_RAG

bash scripts/bootstrap.sh          # secret と .env を作る（初期パスワードが出る）
docker compose build db-migrate    # migrate プロファイルは引数なしの build に入らない
docker compose build
docker compose up -d
docker compose run --rm db-migrate # スキーマ適用と Citus worker 登録

python scripts/load_initial_users.py
```

ブラウザで `http://localhost:8080` を開く。

> **`bootstrap.sh` が表示する初期パスワードを控えること。** 再表示はできない。

## 3. 起動・停止

| したいこと | コマンド |
|---|---|
| 起動 | `docker compose up -d` |
| 停止（データは残る） | `docker compose stop` |
| 停止して片付け（データは残る） | `docker compose down` |
| 状態を見る | `docker compose ps` |
| ログを見る | `docker compose logs -f backend-api` |
| **更新を反映する** | `bash scripts/redeploy.sh` |

> **サービスを選んで `build` しないこと。** migration ファイルも画面の静的ファイルも
> イメージに焼き込まれるため、抜けたサービスだけが古いまま動く。`redeploy.sh` は
> `db-migrate` を含めて全部を作り直し、health を待ち、古いイメージで動いている
> コンテナを検出して入れ替える。

## 4. 画面の使い方

画面は 5 つのタブに分かれる。**検索** / **データ取り込み** / **取り込み履歴** /
**管理** / **パスワード変更**。権限によって見えるタブが変わる。

| 権限 | できること |
|---|---|
| `viewer` | 検索 |
| `operator` | 検索 + 取り込み |
| `admin` | すべて + 利用者管理 |

### 4.1 検索

#### 入力項目

| 項目 | 意味 | 既定 | 使いどころ |
|---|---|---|---|
| **検索モード** | 何で探すか | 画像 → 画像 | 下の表を参照 |
| **検索対象画像** | 検索元の画像 | - | ドラッグ&ドロップでも選択でもよい |
| **所見テキスト** | 所見の文 | - | 日本語可。定型の一覧から選べる |
| **入力言語** | 日本語 / 英語 | 日本語 | 日本語は承認済み辞書で英語化する |
| **画像の重み** | 画像とテキストの配合 | 0.70 | ハイブリッドのときだけ効く |
| **Top-K** | 返す件数 | 10 | 多くすると遅くなる |
| **candidate_K** | ベクトル検索で拾う候補数 | 自動 | 通常は触らない |
| **最小類似度** | これ未満を切り捨てる | 0.0 | ノイズが多いときに上げる |
| **付随ラベル** | 所見での絞り込み | - | **日本語で入る**（結節影, 腫瘤 …） |
| **撮影方向** | PA / AP での絞り込み | - | `PA, AP` のように並べる |
| **サムネイルを表示** | 一覧に画像を出すか | on | off にすると軽い |
| **胸部野の輪郭を重ねて表示** | 比べた範囲（橙の線）を重ねるか | on | |
| **再ランキング** | 所見プロファイルを使うか | on | off にすると BiomedCLIP だけの検索と比べられる |

#### 検索モード

| モード | 入力 | 何が起きるか |
|---|---|---|
| **画像 → 画像** | 画像 | 検索元の胸部野を切り出し、所見の推定（プロファイル）が近い画像を全画像から探す |
| **テキスト → 画像** | 文 | 文を英語化し、同じ空間で胸部野を探す（並べ直しは行わない） |
| **ハイブリッド** | 両方 | 画像とテキストのスコアを重みで混ぜる |

#### 使用例

**例 1: 似た症例を探す**

1. モードを「画像 → 画像」にする
2. 画像をドラッグ&ドロップ
3. 「検索」

1 本の一覧で候補が並ぶ。左端が検索元で、どの画像にも**橙の線（比べた胸部野）**が
重なっているので、何と何を比べたかを見比べられる。

**例 2: 所見の文から探す**

1. モードを「テキスト → 画像」にする
2. 所見テキストに `右上肺野の結節影` と入れる（定型の一覧から選んでもよい）
3. 「検索」

> 辞書に無い自由文は**翻訳せずに拒否する**。品質を保証できない翻訳で検索させるより、
> できないことを伝える方を選んでいる。画面下の「登録済みの定型日本語所見を見る」に
> 使える言い回しが出る。

**例 3: 気胸の疑いで、似た胸郭の症例を並べる**

1. 画像検索を実行する
2. 結果の下部「**胸郭の形が似た症例**」を見る

肺野全体の輪郭で並ぶ。左上が検索元で、**黄色い線が比較に使った肺野の外周**である。
気胸は肺が虚脱して縮み、心拡大は心陰影が広がって肺が外へ押されるので、画素の
見え方ではなく形に出る。

> **所見の判別ではない。** 似た体格・似た写り方の症例を並べて見比べるための軸である。

#### 結果の読み方

| 表示 | 意味 |
|---|---|
| **データセットのラベル** | 放射線科レポートから NLP で導いた、その画像のラベル |
| **所見の推定（研究用・診断ではありません）** | 胸部野の分類器の確率。上位 3 件。0.5 未満は薄く出る |
| 胸部野の抽出が不確か | 片肺が見つからない・左右差が大きいなど。結果は参考値 |
| 所見プロファイルで全件検索 | 画像検索の既定。全画像の所見の推定と厳密に比べた順位 |
| 再ランキング済 | 2 段検索（文章を含む検索など）で、所見の推定の近さで並べ直した候補 |

> **ラベルと推定は別物である。** ラベルはデータセットに付いていたもの、推定は画像から
> 学習した分類器の出力で、どちらも診断ではない。分類器の画像単位 AUC は 0.833
> （全量の評価。所見ごとに 0.70〜0.91）で、浸潤影のように弱い所見もある。

### 4.2 データ取り込み

| 項目 | 意味 | 例 |
|---|---|---|
| **画像ディレクトリ** | 取り込む画像の場所（コンテナ内のパス） | `/imports/nihcc/images` |
| **診断紐づけ CSV** | ラベルの CSV | `/imports/nihcc/Data_Entry_2017_v2020.csv` |
| **データセット版** | 記録に残す版名 | `nihcc-2017-v2020` |
| **CSV schema 版** | CSV の列構成 | `nihcc-data-entry-2017-v1` |
| **件数上限** | 試すときに絞る | `100` |
| **重複時** | 既にある画像の扱い | `SKIP`（残す）/ `REPLACE`（やり直す） |

まず **dry-run** で CSV と画像の突合を確認し、問題がなければ実行する。
1 枚の失敗でジョブは止まらない。失敗は「取り込み履歴」で理由ごとに見られる。

### 4.3 取り込み履歴

ジョブの進行と、失敗の内訳を見る。エラーは CSV で落とせる。
ジョブの取り消しと再実行もここから行う。

### 4.4 管理

利用者の追加・権限変更・無効化。システムの状態（モデルの版、2 段目の充填率、
クラスタの健全性）も見られる。

### 4.5 パスワード変更

自分のパスワードを変える。忘れた場合はログイン画面から再設定を申請すると、
登録したメールアドレスへリンクが届く（開発環境では Mailpit が受ける）。

## 5. 設定

`.env` に集約されている。`.env.example` が雛形で、各項目に説明が付いている。

### よく触るもの

| 変数 | 意味 | 既定 |
|---|---|---|
| `NIHCC_DATA_DIR` | データセットの場所 | `./NIHCC` |
| `ROI_PROFILE` | 肺野の取り方（U-Net が必須） | `nihcc-unet-local-v1` |
| `EMBEDDING_BACKEND` | 1 段目のモデル | `biomedclip` |
| `EMBEDDING_FINE_BACKEND` | 所見プロファイルのモデル（採用構成は `chest-profile`） | `none` |
| `IMAGE_SEARCH_STRATEGY` | 画像検索の進め方（`profile` 全件検索 / `coarse_to_fine` 2 段検索） | `profile` |
| `ROI_MIN_CONFIDENCE` | 検索元の胸部野の信頼度がこれ未満なら結果を抑制 | `0.35` |
| `QUERY_IMAGE_RETENTION_MINUTES` | 検索元の保持期間 | `60` |
| `INGEST_WORKER_REPLICAS` | 取り込みの並列数 | `2` |

> **`.env.example` が更新されたら `python scripts/sync_env.py` で取り込む。**
> 既存の値を保ったまま、増えたキーだけを足す。新しいキーには compose の既定値を
> 使うので、**書き足しただけで挙動が変わることがない**。

### 次元に関わる設定は schema と揃える

`EMBEDDING_DIMENSION` / `EMBEDDING_FINE_DIMENSION` / `EMBEDDING_LUNG_DIMENSION` は
**DB の列の幅と一致していなければならない**。列は migration 実行時の値で固定される
ので、後から `.env` だけ変えると取り込みが全件失敗する。

ingest-worker が起動時に突き合わせて止めるので、気づかないまま進むことはない。

## 6. 困ったときは

[docs/OPERATIONS.md](docs/OPERATIONS.md) に症状別の対処をまとめてある。よくあるものだけ挙げる。

| 症状 | 見るところ |
|---|---|
| 画面が真っ白 / 古い動き | frontend のイメージを作り直したか（`redeploy.sh`） |
| 取り込みが全件失敗 | `.env` の次元と列の幅（OPERATIONS §3） |
| 検索が 503 | 依存サービスの health（`docker compose ps`） |
| 検索が 504 | CPU の取り合い。取り込み中は遅くなる |
| migration が入らない | `db-migrate` を作り直したか |

## 7. 開発

```bash
python -m pytest tests/unit          # 単体テスト

# 起動中のシステムに対するスモーク（admin のパスワードが要る）

```

パスワードは `.env` の `LOCAL_USERS`（`user:password:role` のカンマ区切り）にある。

スクリプトの一覧と用途は [docs/OPERATIONS.md](docs/OPERATIONS.md) §7。
